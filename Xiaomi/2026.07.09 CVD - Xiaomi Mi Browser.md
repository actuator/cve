# Path Traversal via Unsanitized _display_name in ThirdDocViewerActivity in Mi Browser

**Package:** com.mi.globalbrowser

**Impacted Tested Versions:** sink present in 14.58.0-gn (versionCode 202606150)

**Fixed as of ver. 14.66.0-gn**
---

## Affected Files

- `com.miui.docviewer.ThirdDocViewerActivity` — exported, no permission required; handles `ACTION_VIEW` / `ACTION_DEFAULT` for `content://` and `file://` URIs of type `application/pdf` and `text/plain`
- `com.miui.docviewer.CopyExternalFile.copyFromUri(...)` — sink; writes provider stream to `getExternalFilesDir(null)/cache_docs/<unsanitized _display_name>`

---

## Root Cause

For any URI whose authority is not the browser's own FileProvider, `route()` invokes the copy path. The filename is taken verbatim from the provider cursor's `_display_name` column and joined to the staging directory with no basename reduction, canonical-path check, `normalize()`, or separator/`..` rejection:

```java
// CopyExternalFile.copyFromUri(ctx, uri, type, destDir)
Cursor c = ctx.getContentResolver().query(uri, {"_display_name","_size"}, ...);
String name = c.getString(0);                 // attacker-controlled, UNSANITIZED
File out = new File(destDir, name);           // SINK: path traversal
writeFile(ctx.getContentResolver().openInputStream(uri), out);
```

The tainted value originates from the exported entry's `getIntent().getData()` and is never sanitized before reaching the `File` constructor.

## Impact

A zero-permission co-resident app causes Mi Browser to write attacker-controlled bytes under an attacker-chosen filename to an attacker-chosen path within its external storage directory (`/sdcard/Android/data/com.mi.globalbrowser/`), escaping the `cache_docs/` staging directory. No user interaction is required. The write executes as the browser's UID; the attacker controls both the destination path (via `_display_name`) and the file content (via the provider stream). Note: the demonstrated traversal targets external storage rather than internal storage (`/data/data/`), which bounds severity relative to Dirty Stream findings that reach internal databases or shared_prefs — downstream exploitation depends on what Mi Browser reads or loads from its external storage directory.
